# 引子

## 什么是树

客观世界中许多事物存在层次关系，如家谱、社会组织结构、图书信息管理等。
分层次组织在管理上具有更高的效率。
数据管理的三个基本操作：==插入，删除，查找==。

## 查找

给定某个==关键字K==，从==集合R==中找出关键字与K相同的记录

分为：
静态查找：
	集合中记录是==固定==的，没有插入和删除操作，只有查找
动态查找：
	集合中记录是==动态变化的==，还可能发生插入和删除

### 静态查找

一般采用静态数组进行存储

#### 方法1：顺序查找

通过建立一个==哨兵==来省去==循环边界值的判断==。

```
typedef struct Lnode* List;

typedef struct Lnode{

	Elementype Element[MaxSize];
	
	int Length;	
	
} Lnode;

int SequentialSearch1(List arr, Elementype K){
	
	/*Search the element with key K from Element[1] to Element[n]*/
	
	int i;
	
	arr->Element[0] = K; /*Create a sentinel*/
	
	for (i = arr->Length; arr->Element[i] != K; i--);
	
	return i;
}

int SequentialSearch2(List arr, Elementype K){
	
	/*Search the element with key K from Element[1] to Element[n]*/
	
	int i;
		
	for (i = arr->Length; i > 0 && arr->Element[i] != K; i--);
	
	return i;
}
```

顺序查找算法的时间复杂度是$O(n)$。

#### 方法2：二分查找

假设n个数据元素的关键字满足==有序==（比如从小到大）并且==连续存放==（==数组==），那么可以进行二分查找。
- ==链表不支持高效的二分查找==，链表仅支持顺序访问，强行定位中间元素会加大时间复杂度。链表设计初衷为高效动态插入与删除而非查找，故==数组==适用==频繁查找、少量插入删除==，而==链表==适用==频繁插入删除、少量查找==。

```
int BinarySearch(List arr, Elementype K){

    int left = 1, right = arr->Length;

    int mid = (right - left) / 2 + left;

    int ret = -1;

    while(left <= right){

        if (arr->Element[mid] < K){

            left = mid + 1;

        }else if (arr->Element[mid] > K){

            right = mid - 1;

        }else{

            ret = mid;

            break;

        }

    }

    return ret;

}
```

==二分查找算法具有对数的时间复杂度==$O(\log n)$。

启示：

可以将各个元素的二分查找绘制成==判定树==，如11个元素的二分查找判定树（结点内表示数组下标）


![[11元素二分查找判定树.png]]

判定树上每个==结点==需要的查找次数刚好为该结点所在的==层数==。查找成功时==查找次数==不会超过判定树的==深度==，（n个结点的判定树深度为$\lfloor \log_{2}n \rfloor+1$）
==平均成功查找次数（ASL）==由各层结点数乘以层数相加除以总结点数。如11个元素的二分查找判定树为$(4\times4+4\times 3+2 \times 2 +1 \times 1)/11=3$。

# 树的定义和术语

## 树的定义

==树==（Tree）：$n$（$n\geq 0$）个结点构成的有限集合
当$n=0$时，成为==空树==。
对于任一棵==非空树==，它具备以下性质：
- 树中有一个成为“==根(Root)==”的特殊结点，用$r$表示。
- 其余结点可以分为 $m(m> 0)$个==互不相交==的有限集$T_{1}, T_{2},\cdots, T_{m}$，其中每个集合本身又是一棵树，称为原来树的“==子树(SubTree)==”。（注意子树==互不相交==）
- 除了根结点外，==每个结点有且仅有一个父结点==
- 一棵$N$个结点的树有$N-1$条边，所以==树是保证结点联通的边最少的一种连接方式==。

## 树的一些基本术语

- 结点的==度==(Degree)：结点的==子树个数==
- 树的度：树的==所有结点中最大的度数==
- ==叶结点(Leaf)==：==度为0==的结点
- ==父结点(Parent)==：有子树的结点是其子树根结点的父结点
- ==子结点(Child)==：若A为B的父结点，则称B为A的子结点（孩子结点）
- ==兄弟(Sibling)结点==：具有同一父结点的各结点彼此是兄弟结点
- 路径(Path)和路径长度：从结点$n_{1}$到$n_{k}$的==路径==为一个结点序列$n_{1},n_{2},\cdots,n_{k}$，$n_{i}$是$n_{i+1}$的父结点。路径所包含边的个数称为==路径的长度==
- ==祖先结点(Ancestor)==：==沿树根到某一结点路径上的所有结点==都是这个结点的祖先结点。
- ==子孙结点(Descendant)==：某一结点的==子树中的所有结点==是这个结点的子孙结点。
- 结点的==层次（深度）(Level, Depth)==：规定根结点在1层，其它任一结点的层数（深度）是其父结点的层数加1。
- 结点的==高度(Height)==: 规定叶节点在1层，其他任一结点的高度是其子节点的高度加1。
- 树的==深度(Depth)==：树中所有结点中==最大层次==是这棵树的深度。
（注意在英文部分教材及本课程中，结点的深度和高度是从==0==开始，空树的深度定义为==-1==）

# 树的表示

若采用数组实现，则很难判别某个结点的父结点和子结点
若采用链表实现，其中每个结点的结构不同，若采用相同结构表示每一个结点，则会造成空间浪费。

## 儿子-兄弟表示法

对每一个结点都有两个指针 (FirstChild, NextSibling)，一个指向第一个子结点，另一个指向右侧的兄弟结点
![[儿子-兄弟表示法.png]]
既能保证空间浪费较小，又能保证链表中每个结点结构统一。该表示方法不唯一，一棵树的子节点可能是任意顺序

若将右侧链表实现方法旋转45度，即可得到一棵新的树，其中每一个结点最多有两个指针，一个指向左边一个指向右边，这种树成为==二叉树==。
![[二叉树.png]]
故一般的树都可以用二叉树的形式来表示，==二叉树是树中最主要的研究对象==。

typedef struct Tnode{
	
	Elementype Data;
	
	BinTree left;
	
	BinTree right;
	
} Tnode;
